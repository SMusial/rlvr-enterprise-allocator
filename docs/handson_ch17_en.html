🔄 From Single-Agent to Multi-Agent RL

In Ch01–Ch16, one central dispatcher made all decisions. The environment was stationary from the agent's perspective.

In Ch17, each of the 5 technicians is an independent agent. The environment is now non-stationary from each agent's perspective — because other agents are also learning and changing their behaviour simultaneously.
Single-Agent RL (Ch01–Ch16)
• 1 agent, 1 Q-table
• Stationary environment
• Centralised decision making
• π:S→A\pi: S \to Aπ:S→A
Multi-Agent RL (Ch17)
• nnn agents, nnn Q-tables
• Non-stationary environment
• Decentralised decision making
• πi:S→Ai\pi^i: S \to A^iπi:S→Ai for each agent iii

📋 Key MARL Challenges

⚠️ Non-stationarity
From agent iii's perspective, other agents are part of the environment. As they learn, the environment changes — violating the Markov assumption that single-agent RL relies on.
⚠️ Credit Assignment
With shared reward, how does agent iii know if its action was good or bad? The team reward mixes contributions from all agents — making it hard to assign credit correctly.
🔄 Coordination
Agents may need to coordinate (e.g. avoid sending two technicians to the same area) but without communication this is hard. V1–V2 have no coordination mechanism.
📈 Scalability
With nnn agents, the joint action space grows as ∣A∣n|A|^n∣A∣n. IQL avoids this by treating each agent independently, but loses global optimality guarantees.

🤖 V1 — IQL / Individual Reward / No Communication

One sentence: Each technician is a fully independent agent that learns only from its own dispatches, with no knowledge of other agents — the simplest possible MARL baseline.

🧮 IQL Theory

Independent Q-Learning (IQL) applies standard Q-Learning independently to each agent, treating other agents as part of the (non-stationary) environment.

Each agent iii maintains its own Q-table QiQ^iQi and updates it using only its own experience:
Qi(o)←Qi(o)+α[Ri+γmax⁡o′Qi(o′)−Qi(o)]Q^i(o) \leftarrow Q^i(o) + \alpha \left[ R^i + \gamma \max_{o'} Q^i(o') - Q^i(o) \right]Qi(o)←Qi(o)+α[Ri+γo′max​Qi(o′)−Qi(o)]
where:
Qi(o)Q^i(o)Qi(o) = agent iii's value estimate for serving order ooo
RiR^iRi = individual reward received by agent iii for this dispatch
α\alphaα = learning rate · γ\gammaγ = discount factor
max⁡o′Qi(o′)\max_{o'} Q^i(o')maxo′​Qi(o′) = best Q-value for remaining orders (from agent iii's perspective)

📊 What to observe in V1

Expected behaviour:
• Each agent learns independently — high variance between agents
• Agents with matching skills learn faster (higher rewards reinforce good Q-values)
• No coordination — two agents may "compete" for the same order type
• Learning curve: upward trend as ε\varepsilonε decays and agents exploit learned Q-values
• TD Error: converges toward 0 as Q-values stabilise

🤝 V2 — IQL / Shared Reward / No Communication

One sentence: Identical to V1 except every agent receives the same shared reward (team mean) instead of its own individual reward — encouraging implicit cooperation without any communication.

🔄 What changes from V1 to V2

V1 — Individual Reward

Agent TiT_iTi​ receives RiR^iRi = its own dispatch reward.

Qi(o)←Qi(o)+α[Ri+γmax⁡Qi−Qi(o)]Q^i(o) \leftarrow Q^i(o) + \alpha \left[ R^i + \gamma \max Q^i - Q^i(o) \right]Qi(o)←Qi(o)+α[Ri+γmaxQi−Qi(o)]
A lazy agent that serves far-away orders gets penalised directly.
V2 — Shared Reward

All agents receive Rˉ\bar{R}Rˉ = mean team reward.

Qi(o)←Qi(o)+α[Rˉ+γmax⁡Qi−Qi(o)]Q^i(o) \leftarrow Q^i(o) + \alpha \left[ \bar{R} + \gamma \max Q^i - Q^i(o) \right]Qi(o)←Qi(o)+α[Rˉ+γmaxQi−Qi(o)]
A lazy agent is penalised only if the whole team performs poorly.
Rˉ=1n∑i=1nRi\bar{R} = \frac{1}{n} \sum_{i=1}^{n} R^iRˉ=n1​i=1∑n​Ri

⚠️ The Credit Assignment Problem

Credit Assignment Problem: When all agents receive the same shared reward Rˉ\bar{R}Rˉ, how does agent T2T_2T2​ know whether its own action was good or bad?

Example: T2T_2T2​ serves a nearby skill-matched order (good action, R2=+1.8R^2 = +1.8R2=+1.8), but T4T_4T4​ serves a far mismatched order (bad action, R4=−1.2R^4 = -1.2R4=−1.2). The shared reward is Rˉ=1.8+(−1.2)2=+0.3\bar{R} = \frac{1.8 + (-1.2)}{2} = +0.3Rˉ=21.8+(−1.2)​=+0.3.

T2T_2T2​ receives only +0.3+0.3+0.3 instead of +1.8+1.8+1.8 — its good action is under-credited.
T4T_4T4​ receives +0.3+0.3+0.3 instead of −1.2-1.2−1.2 — its bad action is over-credited.

This is the fundamental challenge of shared-reward MARL. V4–V6 address it with more sophisticated methods.

📊 What to observe in V2

Expected behaviour vs V1:
• Smoother learning curve — shared reward reduces variance between agents
• Slower individual learning — credit assignment problem dilutes the signal
• More uniform Q-tables — agents converge to similar values (same reward signal)
• Implicit cooperation — agents are incentivised to improve team performance
• TD Error — may converge slower than V1 due to noisy shared signal

👁 V3 — IQL / Individual Reward / Partial Observability

One sentence: Identical to V1 except each agent can see the positions of all other technicians and uses this information to avoid dispatching to orders already covered by a nearby colleague — distance-aware selection without any explicit communication.

🔄 What changes from V1 to V3

V1 — No Observability

Agent selects order purely by Q-value:

score(t,o)=Qt(o)\text{score}(t, o) = Q^t(o)score(t,o)=Qt(o)
Agent is blind to where colleagues are.
V3 — Partial Observability

Agent scores orders using Q-value + colleague distance:

score(t,o)=Qt(o)+λ⋅dmin⁡−t(o)\text{score}(t, o) = Q^t(o) + \lambda \cdot d_{\min}^{-t}(o)score(t,o)=Qt(o)+λ⋅dmin−t​(o)
Agent avoids orders near colleagues.

🧮 Distance-Aware Selection Formula

score(t, o)=Qt(o)+λ⋅min⁡j≠td(Tj, Wo)\text{score}(t,\, o) = Q^t(o) + \lambda \cdot \min_{j \neq t} d(T_j,\, W_o)score(t,o)=Qt(o)+λ⋅j=tmin​d(Tj​,Wo​)
where:
Qt(o)Q^t(o)Qt(o) = agent ttt's Q-value for order ooo (learned)
λ\lambdaλ = collision avoidance weight (UI slider, default 0.1)
min⁡j≠td(Tj,Wo)\min_{j \neq t} d(T_j, W_o)minj=t​d(Tj​,Wo​) = distance from the nearest other technician to order ooo

Intuition:
• If a colleague is far from order ooo → dmin⁡d_{\min}dmin​ is large → score is boosted → agent takes this order
• If a colleague is close to order ooo → dmin⁡d_{\min}dmin​ is small → score is low → agent avoids this order

This only applies during exploitation (not exploration). During exploration, V3 behaves identically to V1.

📊 What to observe in V3

Expected behaviour vs V1:
• Lower average dispatch distance — agents avoid orders near colleagues, reducing travel overlap
• Higher SLA rate — better spatial coverage means more nearby dispatches
• Nearest Colleague Distance chart — orange bars = overlap avoided (agent chose order far from colleagues)
• Glass-Box "Avoided" column — 🔀 marks steps where collision avoidance changed the selection
• λ effect: λ=0 → same as V1 · λ=1 → strong avoidance, may ignore Q-values

⚠️ Limitations of V3

• No communication — agents observe positions but cannot share plans or intentions
• Greedy avoidance — agent avoids the nearest colleague but doesn't plan ahead
• λ tuning — too high λ ignores Q-values; too low λ = V1. No automatic tuning.
• Individual reward — credit assignment is still clear (same as V1), but no team incentive
• V4 (CTDE) will address these limitations with a centralised critic and full observability.

🧠 V4 — CTDE (VDN) / Shared Reward / Full Observability

One sentence: A centralised coordinator has access to all agents' Q-tables and positions during training and selects the best technician using a joint Q-score (VDN decomposition) — while at execution time each agent still acts using only its own Q-table.

🧮 CTDE Paradigm

Centralised Training, Decentralised Execution (CTDE) is the dominant paradigm in modern MARL.

Training phase: A centralised critic/coordinator has access to the full global state — all agent positions, all Q-tables, all rewards. It uses this information to make better decisions and update all agents' Q-tables.

Execution phase: Each agent acts using only its own local Q-table QiQ^iQi, without any centralised coordinator. This makes the system scalable and robust to communication failures.
V1–V3 (Decentralised)
Training: each agent updates QiQ^iQi independently
Execution: each agent uses QiQ^iQi independently
No global information at any stage
V4 (CTDE)
Training: centralised coordinator uses all QiQ^iQi + all positions
Execution: each agent uses QiQ^iQi independently
Global information only during training

🧮 VDN Decomposition

Value Decomposition Networks (VDN) decompose the joint Q-function as a sum of individual Q-functions:
Qjoint(s,a1,…,an)=∑i=1nQi(oi)Q_{\text{joint}}(s, a^1, \ldots, a^n) = \sum_{i=1}^{n} Q^i(o^i)Qjoint​(s,a1,…,an)=i=1∑n​Qi(oi)
This decomposition allows centralised training while keeping individual Q-tables for decentralised execution.

In our Warsaw ASP implementation:
• Selection: pick tech ttt that maximises Qt(o)+0.5⋅dist_bonus(t,o)Q^t(o) + 0.5 \cdot \text{dist\_bonus}(t, o)Qt(o)+0.5⋅dist_bonus(t,o)
• Assigned agent update: full IQL update with α\alphaα
• All other agents update: soft update with 0.3α0.3\alpha0.3α — they learn from the joint experience even though they didn't act

Expected behaviour vs V1–V3:
• More uniform Q-tables — all agents receive soft updates from every dispatch, not just their own
